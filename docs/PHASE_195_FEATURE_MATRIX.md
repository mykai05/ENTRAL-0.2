Status meanings:

- **Verified** - the bounded requirement itself has direct repository or tag
  evidence and no identified local gap.
- **Local; release pending** - concrete implementation and focused test source
  exist, but the definition of implemented is not closed until the accepted
  commit is merged, tested, deployed, and read back.
- **Partial** - an implementation or evidence gap exists independently of the
  final production release.
- **Blocked** - the requirement depends on a canonical merge, provider action,
  credential, or receipt that does not yet exist.

For every graph item marked **Local; release pending**, production deployment
from the accepted `origin/main` commit and authenticated readback remain
mandatory. A test filename records coverage source; it is not a claim that the
test ran in final CI unless an execution result is explicitly stated above.
